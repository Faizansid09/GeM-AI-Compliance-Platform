GeM Bid Compliance Verification

AI-assisted, officer-controlled compliance verification for government procurement

A transparent dashboard that validates bidder documents, aggregates statutory checks, explains risk, and preserves the human decision and audit trail.

Problem statement: CPCL GeM bid compliance verification
Theme: E-Governance / Procurement Technology
Primary users: Procurement officers and verification teams
Deployment: Browser dashboard + REST backend
Frontend: React, TypeScript, Vite, Tailwind CSS
Integration: Compliance APIs, document processing, audit service

1. Problem Statement

Government procurement teams must verify bidder identity, registrations, statutory filings, local-content declarations, blacklisting status, and supporting documents before taking a tender decision. Manual verification is slow, inconsistent, difficult to audit, and can hide missing evidence.

Proposed solution: one evidence-driven workspace that combines automated checks with clear explanations while keeping the final decision with the authorised officer.

2. Solution Overview

Bidder onboarding

Capture legal name, PAN and GSTIN. Validate formats before documents are sent to the service.

Document verification

Accept PDF, JPEG and PNG files under 10 MB and track asynchronous processing with a job ID.

Compliance intelligence

Display weighted score, risk level, AI recommendation, check status, score and evidence detail.

Human governance

Approve, reject, or override with a mandatory reason. Every action is written to the audit endpoint.

3. Functional Requirements

  1. Select and review multiple tender bidders.
  2. Show complete bidder identity, contact, tender and submission information.
  3. Validate PAN format ABCDE1234F and 15-character GSTIN format.
  4. Upload one or more PDF, JPEG or PNG files, maximum 10 MB per file.
  5. Submit nested bidder data and documents using multipart form data.
  6. Poll verification status every five seconds until Completed or Failed.
  7. Render every compliance check from backend JSON without hardcoded status labels.
  8. Allow re-verification and present a friendly rate-limit countdown for HTTP 429.
  9. Require an officer comment for Approve, Reject and Override actions.
  10. Maintain a visible decision state and audit trail.

5. API and Data Flow

  1. Officer enters bidder details and selects documents.
  2. Client validates PAN, GSTIN, file type and size.
  3. Client sends { bidder: { name, pan, gstin }, documents: [...] }.
  4. Server returns { job_id }; the UI polls /status/{job_id}.
  5. On completion, the compliance query is refreshed and all results are rendered.
  6. Officer submits an action and mandatory comment to /audit.
  7. Override additionally calls /bidders/{id}/override before audit logging.

6. AI/ML and Explainability

  • AI recommendation is advisory and never silently changes the officer decision.
  • Every recommendation is accompanied by score, risk level, check status and details.
  • Manual-review states expose uncertainty instead of forcing a binary result.
  • Future model versions should store model ID, input evidence references, confidence, timestamp and explanation.
  • Human override is always available and requires a recorded justification.

7. Security and Reliability

Security

  • JWT/OIDC authentication in production
  • Role-based officer permissions
  • HTTPS and encrypted document storage
  • Input validation and malware scanning
  • PII masking in logs

Reliability

  • Timeouts and readable errors
  • Retry policy for transient queries
  • Rate-limit handling with countdown
  • Idempotent audit requests
  • Immutable audit history

9. Judging Criteria

  • Impact: reduce verification time and improve consistency for procurement teams.
  • Innovation: explainable AI plus mandatory human governance, not an opaque auto-decision.
  • Feasibility: modular REST integration and asynchronous processing fit existing government systems.
  • Security: evidence protection, role controls and traceable decisions.
  • Usability: one-screen review, clear status, no blank states, and meaningful errors.
  • Scalability: supports more bidders, checks, portals and verification models without UI rewrites.

10. Expected Demo Flow

  1. Open the dashboard and select a bidder.
  2. Show bidder information, score, risk and compliance breakdown.
  3. Enter an invalid PAN/GSTIN to demonstrate instant validation.
  4. Upload a supported document and submit for verification.
  5. Show Processing status, completion refresh and error handling.
  6. Click Override, demonstrate the mandatory reason, and show recorded decision.

11. Likely Judge Questions and Answers

QuestionSuggested answer
Does AI make the final decision?No. AI only provides decision support. The authorised officer approves, rejects or overrides with a mandatory reason.
How do you prevent incorrect identifiers?PAN and GSTIN are normalised and format-validated in the browser, then validated again by the backend.
What happens during long verification?The server returns a job ID. The UI polls every five seconds and shows a local Processing state instead of freezing the page.
How is the result explainable?The score is broken into named checks with status, points and evidence details; uncertain checks become MANUAL_REVIEW.
How is tampering detected?Production design uses immutable audit events, actor identity, timestamps, document hashes and server-side permission checks.
Can it scale to other government portals?Yes. Portal adapters can normalise source responses into the common compliance-check contract.
